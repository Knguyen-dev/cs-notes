We're trying to minimize the number of branches, especially in the middle of our loops.

## Example 1: Very Simple
```cpp
int smaller(int a, int b) {
  if (a < b) {
    return a;
  } else {
    return b;
  }
}

int smaller_branchless(int a, int b) {
  return a*(a < b) + b*(b <= a);
}
```
A common thing you'll see in branchless programming is the use of arithmetic. Then we can reason:
- If a < b, then the expression is `(a * 1) + (b * 0) = a`, so return `a`.
- Otherwise return `b`.

The general form of this is: a * (condition for a) + b * (condition for b) + ... etc. However, you'll see that the branchless version is actually slower. Modern compilers are really good at optimizing our code and also making our code branchless. Sometimes by trying to make our code branchless manually, we're making it harder for the compiler to optimize our code. In general, if you're doing performance tuning, take a look at the ASM code generated by the compiler. You can probably immediately see whether something is slower by comparing the amount of ASM instructions needed to represent the two functions.

## Example 2
```cpp
void toupper_1(char* d, int count) {
  for (int i = 0; i < count; i++) {
    if (d[i] >= 'a' && d[i] <= 'z') {
      d[i] -=32;
    }
  }
}

// Fast
void toupper_branchless(char* d, int count) {
  for (int i = 0; i < count; i++) {
    d[i] = (d[i] * !(d[i] >= 'a' && d[i] <= 'z')) + 
    (d[i] - 32) * (d[i] >= 'a' && d[i] <= 'z');
  }
}

// Faster
void toupper_branchless2(char* d, int count) {
  for (int i = 0; i < count; i++) {
    d[i] -= 32 * (d[i] >= 'a' && d[i] <= 'z');
  }
}

```
Let's say we want to have a function that uppercases a lowercased ascii to an uppercase ascii character. This is simply done by subtracting 32 from the character's numerical representation. Above is our standard C++ representation. If you disassemble this, it doesn't take long to notice that that are quite a few branches or jumps in the ASM version. We can then potentially improve this using techniques we saw in our first example.

## Takeaway
In most cases you won't outsmart the compiler. For high level programming, focus on keeping your code clean and easy to read/maintain. Usually you'll notice speedups by using correct algorithms and data structures, not by adding clever micro-optimizations. If speed is a concern, benchmark first and then optimize second.
